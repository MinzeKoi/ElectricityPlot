### 失败机制与交接边界

拟议方案在主预算出现 2 个水壶全关案例，20 次出现另外 3 个；均指共同有效评价支持上的预测全关，没有全开案例。全部 5 个案例仍符合原参数限幅，说明当前限幅仍允许功能性塌缩。主预算 seed 42/query 2026 的水壶有 1 正、2 负、1 unsure，偏置达到 -ln(2)，斜率保持 1；原 2000 W 阈值的等效开机阈值变为 4001 W，在 137,523 个有效点上全部预测关闭，而真实开机点为 1012。seed 1019/query 1019 的偏置为 -0.485162，等效阈值约 3249.5 W，同样全关。完整模型参数与回答计数保存在结果 JSON。

这是已保存模型与失败输出的直接机制记录，不作为新修复的效果证据。R1 固定确认序列的正收益保留；本轮不同查询轨迹下的不稳定性也保留，不能把固定序列收益推广为所有选片策略都有效。来源结构贡献、确认收益、策略收益继续分别陈述。

本轮有限选片比较到此结束，不再追加评分项或调权。下一步应优先在独立的新开发版本中处理混合回答后的状态退化，再验证确认稳定性；重新满足方法与数据资格后，另建最终配置/协议。当前不启动 R3 正式评价，不继承旧 A5 主方法身份。状态确认未改变功率、电量或未解释负荷，本轮不提供 H3 改善证据，也没有真实用户确认或最终跨户效果结论。

## 运行方式

使用具备锁定 CPU 依赖的 Python；本机可用环境为 `.venv-m4`。`--r1-fixed` 可指定恢复后的完整父运行路径。

从 GitHub 恢复已同步的父运行时，先取 Git 对象与限定子树的 LFS 文件，再使用恢复辅助入口。它只读取该 R1 子树，核对 LFS 大小和 SHA-256，不覆盖已有目录，不改变 Git 检出或索引，不解析目标标签 CSV；远程缺失的派生目录仍由后续 preflight 按原规则判断。

```powershell
git fetch origin main
git lfs fetch --include="outputs/accuracy/r1-fixed-20261022-v2/**" --exclude="" origin f266b762b752b32a31810d916d198ccc06f7ec51
.\.venv-m4\Scripts\python.exe scripts/restore_r2_parent.py --check-only
.\.venv-m4\Scripts\python.exe scripts/restore_r2_parent.py
```

若 Git LFS 的 TLS 连接失败，可使用本轮已实际验证的 Windows HTTPS 入口（PowerShell 7），仍按固定提交和原始哈希恢复：

```powershell
New-Item -ItemType Directory outputs/r2-start-20261023 -Force | Out-Null
.\.venv-m4\Scripts\python.exe scripts/restore_r2_parent.py --check-only > outputs/r2-start-20261023/lfs-check.json
pwsh -NoProfile -File scripts/fetch_r2_lfs_windows.ps1 -CheckReport outputs/r2-start-20261023/lfs-check.json -Throttle 12 -ConnectionTimeout 45 -OperationTimeout 180
.\.venv-m4\Scripts\python.exe scripts/restore_r2_parent.py
```

该入口只记录对象身份与结果，不输出临时签名下载地址。已校验对象自动跳过；请求失败保留已收到的片段，后续按范围续传并在完整文件上核对原始大小和 SHA-256。文本文件受 Git 行尾转换影响时，只接受能够匹配原始封存哈希的字节恢复，不重写封存哈希。

```powershell
.\.venv-m4\Scripts\python.exe scripts/run_r2.py preflight --r1-fixed outputs/accuracy/r1-fixed-20261022-v2
.\.venv-m4\Scripts\python.exe scripts/run_r2.py freeze --r1-fixed outputs/accuracy/r1-fixed-20261022-v2 --output outputs/accuracy/r2-20261023
.\.venv-m4\Scripts\python.exe scripts/verify_r2_boundaries.py --run outputs/accuracy/r2-20261023 --output outputs/my-r2-boundaries.json
.\.venv-m4\Scripts\python.exe scripts/run_r2.py evaluate --run outputs/accuracy/r2-20261023
.\.venv-m4\Scripts\python.exe scripts/run_r2.py verify --run outputs/accuracy/r2-20261023
```

`freeze` 要求新输出目录；仅在冻结中断且输入/源码未变时用 `resume` 替代 `freeze`。恢复完成后另行 `evaluate`。`run` 将冻结及评价连续执行；`preflight --report 新文件.json` 可保存检查回执。输入缺失和核验失败均返回非零退出码。

真实运行 `outputs/accuracy/r2-20261023/` 已保存 `frozen/`、`freeze.json`、`metrics.json`、`summary.json`、`comparison.csv`、`query_distribution.json`、`report.html` 与 `evidence.json`，包括自身收益、相对随机收益、逐设备逐种子差值及实际回答分布。工程通过与效果未达标分别记录。

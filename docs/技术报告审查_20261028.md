## 1. 主实验模型结构写得不准确，必须说明独立网络组合

**位置：PDF 第 4 页，2.2.1；TeX 第 181—211 行。优先级：高。**

正文仅写“8 个卷积通道、32 个隐藏单元”的小型 CNN，容易被理解为三设备共享一套网络。第 17 号家庭确认实验和默认交互所依托的 R1 来源模型，实际选中的是 `single_mae`：三个设备分别训练，再按分块对角权重组合。

- 每个组件为 8 通道、32 隐藏单元，独立选择检查点。
- 三个组件实际训练参数合计 24,747。
- 兼容通用接口的稠密封装为 24 通道、96 隐藏单元，共 73,707 个存储参数；跨设备连接为零。
- 原共享三输出模型为 8,315 参数，两者不能混为同一参数预算。

建议把现有结构描述限定为“单个设备组件”，再补一段组合方式与参数量，并明确表 4 对应这一组合模型，表 7 对应早期模型。功率公式（2）（3）本身可保留，但应交代各组件分别拟合。

## 3. PDF 附录命令丢失空格，无法直接复制执行

## 4. 附录创建的环境与启动脚本不匹配

**位置：PDF 第 15 页，A.1；TeX 第 755—769 行。优先级：高。**

附录先创建 `.venv-paper`，随后让用户运行 `start.cmd`。实际启动脚本只寻找 `.venv-m4`、`.venv-m2` 和 `.venv`，不会发现 `.venv-paper`。在只有文稿所建环境的新机器上，启动会报找不到项目环境；如果已有旧环境，则可能启动旧环境。

最小修改是统一采用已验收的 Python 3.12 环境及 `.venv-m4` 名称：

```powershell
py -3.12 -m venv .venv-m4
.venv-m4/Scripts/python.exe -m pip install -r requirements-m4-cpu.lock
git lfs pull
start.cmd
```

正文可以继续说明 Python 3.11+ 是项目声明支持范围，同时单列“本文验收环境为 3.12.14”。不能把全部更高版本都写成已验证。若保留 `.venv-paper`，则应统一使用该解释器的直接启动命令。

证据：[启动脚本](<D:/system position/document/真正的文档/AIC/start.cmd:7>)。

# Task25 采样对照：解释与固定条件（2026-10-28）

## 本次能回答什么

Task24 三种子来源 F1 平均从控制的 0.38760 降到 0.36336，未通过既定来源资格；原三户各自及其全部 290 个来源正例采样片段的呈现次数均降至旧实验的约三分之一。见 `docs/F1_TASK24_FINDINGS_20261028.md`。拟议 Task25 保持同一个七户来源训练池，将每种子正例槽位中原三户份额从 Task24 的约三分之一调整为三分之二，对照已封存 Task24。这个固定预算下的比较可检验：**按本方案重新分配正例采样后，固定来源验证表现如何变化**。

它不能单独证明 Task24 失败就是旧户曝光下降造成的：正例总槽位不变时，增加旧户份额必然减少新增户份额，旧/新组内片段与中心的具体呈现也会改变。它也不能证明家庭多样性或事件数量无效、否定其他采样配比或预算、解释模型全部误报成因、证明未见户泛化；结果只适用于固定来源验证及本项训练配方。即使好于 Task24，也不自动超过原 `control_guard95` 或证明开发 F1 提升。

原正例采样按照 `(house, UTC日)`、该组中的片段、片段中的中心依次轮转，**不是先对家庭等权抽样**；明确区分采样片段与独立物理事件。原实现见 `src/virtual_submeter/accuracy/microwave_sampling.py` 的 `BatchStream`；Task24 实际计划与曝光见 `outputs/accuracy/microwave-task24-preparation-delivery-20261027-v1/报告.md`。

## 实现和可复核的对照约束

- 各种子沿用 Task24 的同一 3,528×256 索引矩阵结构：每批原有 240 个负例索引、位置及相对顺序逐批精确重放，只替换原 16 个正例槽位。原 `BatchStream` 将正例、负例和批内打乱共用随机流；仅用同一随机种子重跑并不能保证负序列不变。正例采用独立、固定的随机流，组内保持上述 `(house, UTC日)→片段→中心` 规则。
- 16 不能被 3 整除，固定三批循环旧户正例数 **11、11、10**，对应新增户 **5、5、6**；每种子恰为旧户 37,632、新增户 18,816 次正例呈现。旧/新成员及正负标签以封存的来源身份校验；输出每种子、户、日、片段及中心的实际曝光和重复情况。不要以“每批恰好三分之二”描述 11/11/10。
- 沿用 Task24 七户固定池、来源验证区间、输入归一化及掩码、16 通道网络、unit BCE、Adam、三种子、每种子 3,528 更新、12 次每 294 步检查；逐 tensor 核对同种子初始化，固定训练批大小和 CPU 配置。只读复用 Task24 候选用于对照，不重训。
- 来源检查点沿用原 85% 保护及排序；沿用来源 L95/H95、半径 15 的校准算法与规则，而不是照搬另一模型的数值阈值。资格仍相对冻结 `control_guard95`：逐块 R≥95%、非退化、平均 F1 不低于控制、各种子平均召回下降不超过 0.05、至少两个种子 Precision 提高。按既有来源排序决定结果；Task24 是固定的解释性比较对象，不替换控制资格或事后修改门槛。
- 准备和复核应证明三个种子逐批负槽与初始化一致、正槽份额及成员正确、日期片段边界不混、旧结果不改，记录汇总与完整索引。该阶段零训练、零候选推理，不读取开发/最终数据。若来源未通过，不进入开发评价；不得在结果出来后改比例、选其他检查点、延训或扩搜索。

## 另一种直接对照及限制

同预算下，固定七户池与负槽、将正例全部分配给原三户（100% 旧户）可更接近旧实验的正例总曝光；但它同时把新增户正例曝光降为零，而且旧组内抽样顺序和训练负例仍与 Task12 不同，不能成为对“曝光是否是唯一根因”的完全隔离实验。它不比当前 2/3 对照普遍更优，也会改变当前已约定的候选；这里只记录解释，不增设或搜索该方案。

当前授权仅为零训练准备与独立复核；最多拟新增三模型、合计 10,584 次更新的预算，须在准备结果可审查后由用户单独批准。本文件本身不授权训练、推理或开发验收。来源通过也不自动切换默认模型，功率及电量效果不能从状态分类结果推断。

# 双人协作约定

默认 A 负责数据与算法，B 负责工程与演示。具体日程和任务见 [PLAN.md](../PLAN.md)。

## 本地仓库与共享

初始化创建本地 Git 仓库，不预设远程平台、公开性或账号。团队审阅初始文件并完成首次提交后，再配置双方可访问的远程仓库、各自克隆。原始数据按各自本机路径准备，不放入 Git；共享配置只用相对路径。

建议分支：`feature/data-protocol`、`feature/baseline`、`feature/weak-adaptation`、`feature/ui`、`feature/reporting`。短分支一次只处理一个任务，合并后尽快同步主分支。不要强制推送共享分支或覆盖对方修改。

## 每项任务的最小约定

开始前记录：负责人、输入/输出、验收条件、依赖接口和预计交接日期。接口有变更先更新数据契约，提供小型合成样例，再由另一人适配。

合并说明包括：改了什么、如何运行、验证结果、未完成内容、是否改变数据划分或指标。由另一人审查后合并。高风险改动包括标签权限、划分、指标、查询预算、权重加载和结果状态。

## 每天一次交接

用简短文字说明已完成、实际证据、阻塞项、下一步。不要把仅运行过的代码说成达到实验目标。需要对方配合时给出可复现输入和命令。

A 给 B 的最小交接：数据字典、冻结划分、预测字段、合法缺失值和一个合成样例。B 给 A 的最小交接：导入/查询/推理/导出的接口、错误结构和运行记录格式。

两人应至少各自复跑一次对方的关键流程。B 使用测试标签检查结果时，不把答案回传给选片或适配模块。数据代理模拟的确认记录与真实用户回答分开保存。

## 材料与数据保护

原始数据、权重、运行输出、账号与密钥不提交。不要在截图、日志、配置中泄露本机账号或路径。公开研究和数据按许可引用，署名与比赛匿名材料分别处理。

# 微波炉精确率受控实验

日期：2026-10-24。负责人：本次开发会话。输入为扩数实验 A 组的已冻结数据、三种子微波炉权重及其他设备预测；输出为独立 `outputs/accuracy/precision-20261024-v1/`。旧实验、默认界面模型和最终家庭 8/9/20 保持原状。

## 预定实验与出口

使用来源 2/19 原14天、验证5、已查看开发17。固定八秒网格、31点上下文、8通道、32隐单元、Adam 0.001、batch256、587步×12检查点，按来源验证 normalized MAE 选择检查点。三种子42/1019/2026；基准 W50 先全部通过历史逐参数复现，再训练 W10/W1。

第一阶段三权重×三种子共9个微波炉网络。按来源验证选择权重后，以各自模型在来源训练窗口中挖掘“真实关闭且预测≥200 W”，固定该集合，将这些点权重由1改为4，再从相同种子重新训练3个网络。缺少困难负样本时采用普通权重并保存空集合。不会扩展候选或按开发结果改配方。

候选要求来源平均F1不低于W50、每种子Recall下降不超过0.05、至少两个种子Precision提高、无全开/全关且共同支持一致。排序为平均Precision、平均F1；同分按W50、其HN、W10、其HN、W1、其HN优先。第一阶段无通过者用W50挖掘；最终无通过者选W50保留原模型。开发评价前封存选择、全部12个模型和24份验证/开发组合预测。

开发出口：平均Precision≥0.08；每种子Recall≥0.85；平均微波炉F1提高≥0.02；至少两个种子Precision与F1同时提高；任一种子F1下降≤0.02；平均FP减少≥30%；无新增全开/全关；评价支持相同；水壶/洗衣机原始预测逐点一致。功率一致性修正另算，其变化不算其他设备原始状态改变。

## 接口与复跑

新增入口和配置：`scripts/run_precision.py`、`configs/precision_20261024.json`。各命令依次执行；新输出必须不存在，已完成实验禁止覆盖。

```powershell
.\.venv-m2\Scripts\python.exe scripts/run_precision.py prepare --run outputs/accuracy/precision-reproduction
.\.venv-m2\Scripts\python.exe scripts/run_precision.py train --run outputs/accuracy/precision-reproduction
.\.venv-m2\Scripts\python.exe scripts/run_precision.py evaluate --run outputs/accuracy/precision-reproduction
.\.venv-m2\Scripts\python.exe scripts/run_precision.py verify --run outputs/accuracy/precision-reproduction
```

训练中断时只允许在相同源码、配置、数据和权重下使用 `train --resume`。已完成模型会逐项核对后复用，不增加训练候选。基准复现不一致立即中止，不跳过核验。准备失败的目录保留原因，需新建目录重跑。

运行目录保存源码快照和 `entrypoints/run_precision.py`；未来工作区源码改变时，可用该封存入口复核原实验。入口先关闭字节码写入，再加载封存包，不向封存源码添加缓存文件。普通离线 `verify` 不重新解析开发标签，核验输入、模型、预测、选择和结果哈希，并从已保存指标重建选择和出口。

训练接口 `train(..., negative_weights_path=None)` 默认保持旧行为；非空时读取与本次协议绑定的来源窗口清单。`dataset(..., return_keys=True)` 在原三项返回值后增加来源家庭与中心时间标识。窗口权重按标识对齐，未知、重复、开机或缺失标签窗口均拒绝；不会按CSV行号绑定。

## 产物

- `registration.json`、`freeze.json`：运行前输入/源码登记、全矩阵封存和选择先于评价的证据。
- `reference_checks/`：三种子 W50 逐参数复现；`readback.json`：全部12个候选与普通预测入口在来源验证前2033行的原始功率、状态及缺失位置对齐。
- `negative_windows/`：窗口身份、来源模型/协议哈希、每户数量和空集合说明。
- `source_metrics.json`、`stage_one_selection.json`、`selection.json`：只依据来源验证的预定选择。
- `comparison.csv`：全部候选、种子、分区、设备及原始/修正功率视图指标；`summary.json`：预定候选的逐项出口。
- `error_segments.csv`、`error_curves.csv`：基准与预定候选的误报、检出、漏报连续段及同区间曲线。片段仅用于评价后分析，不回流本轮训练。
- `report.html`、`evidence.json`：易读报告及评价产物哈希。

本轮只有单个已查看开发家庭；来源训练种子不等于独立家庭。核心流程的普通预测读回为固定样本核验，不能表述成全部12个模型的未来点均已逐点通过普通入口重放；额外完整读回的实际范围见下文。

## 实际执行结果

真实运行已完成12个微波炉模型、24份来源验证/开发预测、144行设备/视图指标。W50 三种子均与历史 A 组逐参数一致，差值为0。执行源码指纹及全部输入、模型、预测、来源选择、指标与报告已保存；工作区入口和封存源码入口的最终复核均通过。

来源筛选没有新候选通过：W10 的来源平均 Precision 为0.2273，高于W50的0.1679，但三个种子Recall分别只有0.6391/0.6489/0.6242，均超出预定下降保护。W1来源平均F1为0.1471，低于W50的0.2786。因此按预案以W50挖掘困难负样本；W50_HN来源平均Precision/F1为0.1110/0.1921，也未通过。最终选择在开发评价前固定为W50，没有看开发成绩后重新选择。

不能把W1较高的F1或较小的总电量误差写成方案通过：任务同时要求逐种子召回保护，且其运行段MAE从约538 W恶化到1116 W。当前证据说明单纯减少开机加权会改变Precision/Recall取舍，固定4倍困难负样本加权也没有产生可接受的识别收益；不由此证明所有损失或负样本方法普遍无效。

## 1. 总体判断

项目已经具备较完整的研究工程闭环：真实数据导入、基线训练、预算内弱确认、适配、未解释负荷、报告和实验封存均有实现。接下来最影响成果质量的是基础识别能力、有效确认信息和真实跨户证据。

核心研究主张“少量用户确认提高新家庭识别精度”仍未完成最终验收。当前收益主要来自一个已查看开发家庭，绝对识别精度偏低，部分收益表现为收到负回答后压低分数；尚不足以证明系统已具备面向普通家庭稳定使用的精度。

建议路线为：**可用数据与角色冻结 → 基础识别与固定确认学习 → 少量查询候选比较 → 新家庭统一封存评价 → 同一方法接入界面 → 可复现交付。** 功率联动保留为独立研究分支。10 月 24 日后停止新增算法候选，优先完成证据与作品。

## 3. 当前不足与优先级

### P0：数据量已扩大，可用实验支持仍不足

现有模型实际仍主要来自一户来源训练、一户来源验证和 House 3 的短开发区间。20 户完整文件不会自动增加已训练家庭数。

新增六个候选家庭 6/8/9/17/19/20，在所取最早 28 天的适配/未来标签覆盖约为 17%–40%，没有达到现有 90% 门槛。当前八秒处理对每次观测最多维持八秒，只保留完整覆盖的八秒区间；原始记录中较长且不规则的时间间隔会使派生数据缺失。因此需要区分原始缺测、采样间隔、上游清洗、Issues 标签屏蔽和本项目严格重采样各自的影响。

这是根据交接和实现得出的排查方向，尚未完成原因分解；不能预先判断换一段日期、延长记录或改变网格就一定能解决。具体实现见 `data/prepare.py` 的 `resample`，资格逻辑见 `data/final_protocol.py`。

### P0：基础识别和有效确认信息不足

当前 A2/A3 主设备零确认 F1 约 0.176，微波炉误报明显，洗衣机仍有扩展质量问题。以这样的基础表示继续增加选片项，收益可能受限于模型本身。

A3 拟议主预算的九条种子轨迹合计 90 次模拟回答中，0 正、37 负、53 不确定；水壶没有正回答。A2 的三条最长随机轨迹也未取得水壶正回答。当前结果尚未充分验证“从正窗口学会新家庭设备活动”，需要扩大开发事件支持并分析不确定回答来源。

### P0：研究方法与界面确认流程尚未统一

`app/confirmations.py` 仍调用旧 `adaptation.session` 和 `adaptation.training`；新 A2/A3 学习器与动态会话位于 `accuracy/`。界面已有确认功能，不能据此认为新方法已经完整接入。`dashboard.py` 还只按旧适配类型生成阶段提示。

现有界面比较按钮会直接执行所选家庭的测试评价。正式盲测期间应由独立实验入口管理统一开封，避免通过界面提前看到局部最终结果。后续界面可读取已封存报告，开发演示保留明确的数据用途标识。

### P1：选片复杂度、可信表述和复现证据需要收敛

静态不确定性及若干删减消融优于完整拟议策略，表明当前增加的刷新、多样性、覆盖项没有得到收益支持。A4 收益也主要伴随负回答，不能视为已学到目标真实瓦数。来源残差区间没有跨户覆盖保证，状态分数未校准，不宜展示为可靠概率。

独立人员与第二台机器复跑、真实用户回答、外部数据集验证仍待完成；原始运行和权重依赖本机路径，部分历史产物还有权限视图差异。需要形成可以交给另一人的完整证据包。

### R1：提高基础识别并巩固 H1，10-23 至 10-24

负责人 A；B 维护共同评价支持和结果对照。

优先水壶、微波炉，洗衣机继续作为扩展设备完整报告。先使用已明确归入开发的家庭/区间，尽量增加一至两个开发目标及合格来源支持；不足时减少探索范围，不占用已留出的最终家庭。旧 House 3 可保留作历史诊断，其场景资格限制一并披露。

来源模型候选总数不超过三个：当前小型多设备 CNN 作为对照；同骨干的单设备方案用于检查共享训练干扰；第三个候选只处理已由错误分析支持的问题，例如事件/关闭样本平衡或时间上下文。先固定一个筛选种子比较，选定后再训练全部来源种子，不继续挑最好的种子。

按来源验证与开发数据的预先固定联合规则选择模型，同时看逐设备 Precision/Recall/F1、运行段 MAE、电量误差、全关/全开。检查来源样本比例和模型选择指标的匹配性，避免仅凭全时段误差选择大量误报的模型。所有比较采用相同时间支持。

然后固定查询序列，只保留有界偏置与受保护 L2 两个必要学习器比较。每个学习器都与自身零确认比较，保留限幅、来源回放、单类回答保守规则；来源结构带来的增益单独记录。对不确定回答区分标签缺失、事件支持不足和回答语义，不能全部解释为用户不愿回答。

只有在开发证据支持时，额外比较一种较短确认窗口与原 20 分钟窗口；窗口信息量、上下文与预算公平性重新说明。候选池依赖总表/模型，不能使用未查询分表挑正例，也不能反复抽查询种子直到出现正回答。

交付物：冻结来源模型、固定确认比较、逐户/逐设备配对差值、有效回答分布、完整事件支持与负结果。新来源训练或学习器变化必须生成新版本，不能接续为旧 A2/A5 的同一实验。

出口：确认前后产生可重复正收益，且无新全关/全开。若只有旧单户的小幅收益，主结论保持开发性；H1 的最终门槛仍为主预算提高 0.05、至少三分之二最终家庭为正，不通过改预算或降低门槛宣布通过。

### R4：让界面实际使用选定方法，10-23 至 10-27

由另一位成员在独立环境至少复跑关键预测、确认适配和报告重建；条件允许再用第二台机器。明确区分同机不同成员、同机新环境、第二机器和完整训练复跑，不合并成一句“已独立复现”。

打包包含代码快照、未提交修改对应的源码证据、依赖锁定、数据获取和许可说明、实际必要权重、配置、哈希清单、查询记录、预测、指标与报告。启动入口不能依赖只有本机存在的历史目录。旧实验使用对应源码版本复核，不关闭其源码一致性检查。

交付材料中每个关键数字都能追溯到具体运行及汇总口径。报告同时呈现成功与失败案例；公开实测、合成注入、模拟确认、操作试用分别标明。应用价值表述以分项估计和分析辅助为限，实际节电与账单收益需要后续现场证据。

## 6. 结果不足时如何收敛

| 决策条件 | 保留的成果与下一步 |
|---|---|
| 10-23 仍无三户原规则合格最终家庭 | 保留失败资格记录；新协议另立项或如实报告有限真实开发结果，最终盲测不冒称完成 |
| 基础表示仍弱，固定确认不能稳定改善 | 停止复杂选片扩展；聚焦基础识别、抗退化设计和负结果分析 |
| H1 通过，H2 不通过 | 主张确认驱动适配；采用经开发冻结的简单策略，披露组合策略未获支持 |
| 状态改善，H3 不通过 | 保留状态结果；功率/电量继续作为独立未解决问题 |
| 只有少量家庭或某设备表现差 | 报逐户/逐设备结果和支持；不在看最终分数后删除困难设备 |
| 10-27 仍有大范围实验或环境故障 | 冻结已核实证据，保证稳定演示与完整材料；故障项目明确标注未完成 |

本轮暂缓新增复杂骨干、大模型解释助手、云端多用户、硬件接表、更多电器，以及多个外部数据源同时训练。可以保留离线能源分析原型的价值，但“稳定跨户识别”“真实用户少量确认有效”和“实际节电”分别需要对应证据。

## 7. 提交后四至六周路线

1. **第一至二周：扩大可靠跨户验证。** 完成更多合格来源与开发家庭、独立最终家庭或留一户验证，按家庭汇总稳定性；完善事件指标、运行段误差和回答噪声/跳过敏感性实验。用新开发证据决定是否值得进一步投入复杂选片。
2. **第二至三周：接入一个外部来源。** 优先利用已下载 Plegma，单独建立十秒数据契约和匹配模型；或者核验并取得 UK-DALE 的有功数据。一次只做一个适配器，冻结哪些家庭用于开发、哪些留作外部测试。跨源效果以实测结果为准。
3. **第三至四周：开展真实确认试验。** 在能够获得同期总表及可靠使用记录的少量家庭中，评估每户 5/10/20 次确认的耗时、回忆错误、正例稀缺和适配收益；如采集分表真值，先确定数据与参与者约定。离线公开数据代理不替代真实回答。
4. **第四至六周：按证据推进功率和可信输出。** 状态收益稳定后再扩大 A4；划出未用于模型选择的校准支持，评估覆盖率与区间宽度、误归因与可归因比例。无充分验证时继续保留未解释部分和未校准说明。

IDEAL 当前只有说明和元数据，后续先按有功测量、目标通道和家庭角色筛选，再决定是否获取大型测量包。扩充资源以解决明确的验证问题为前提。
